# apic v0.5.1

## 新功能

- **`-f key=value` 按定义的字段类型转换**：JSON 请求体的顶层字段在定义里声明为 `boolean`、`integer`、`number` 时，`-f key=value` 按该类型发送。
  - `-f mock=true` → `{"mock":true}`，`-f n=3` → `{"n":3}`。
  - 值不合法时退出 1，如 `field "mock": "yes" is not a valid boolean (use mock:=<json> to send it as written)`。boolean 只接受 `true`、`false`；integer、number 必须是合法的 JSON 数字（`+5`、`007`、`Inf` 不接受）。
  - 类型来源：OpenAPI / Swagger 的请求体 schema；简单定义新增的 `body.fields`。
  - 不变的情况：`-f key:=<json>` 按写的原样发送；带点的键（`a.b=v`）、未声明类型的字段、`string`/`array`/`object` 字段仍发字符串；form 与 multipart 请求体仍是文本。
- **简单定义 `body.fields`**：声明请求体顶层字段的类型，取值 `string`、`integer`、`number`、`boolean`、`array`、`object`，写错时加载定义报错（退出 1）。`apic desc` 的 BODY 部分列出这些字段。

  ```yaml
  operations:
    trigger:
      post: /api/trigger
      body: {fields: {mock: boolean, retries: integer}}
  ```

## 修复

- `-f`、`-F`、`-p`、`-H` 的帮助文字中 `(repeatable)` 显示了两次。

## 兼容性

- 对 OpenAPI 站点，已声明为 boolean/integer/number 的字段，以前 `-f key=value` 发字符串，现在发对应类型；值不合法的调用（如 `-f n=abc`）现在在本地报错退出 1，不再发出请求。需要原样发送时改用 `-f key:=<json>`。
- 使用了 `body.fields` 的简单定义，在 v0.5.0 中会忽略该键，回退无需改配置。
