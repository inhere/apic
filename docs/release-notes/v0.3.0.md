# apic v0.3.0

## 新功能

- **overlay**：在 `<配置目录>/overlays/<site>.yaml` 里修正站点定义，不用改上游 spec，`site refresh` 后仍然有效。
  - 可以给操作改名、隐藏操作、修改摘要，以及修改请求体类型和输出格式；
  - 可以修正参数的必填、类型、枚举和说明，隐藏参数，或补上 spec 漏写的 query/header 参数；
  - 调用、`ops`、`desc`、补全和 `apic skill` 都按覆盖后的结果工作，`desc` 会标出改过的字段和隐藏参数。

  `apic overlay init <site>` 生成模板，`apic config check` 检查 overlay 的错误。hide 不是访问控制，隐藏的操作仍能用原始路径调用。
- **文件上传**：用 `-F name=@path` 发送 `multipart/form-data`，可以附带 `;type=` 和 `;filename=`。
  - 只读普通文件，写保护检查通过后才读，请求体上限 64 MiB；
  - `--dry-run` 打印的 curl 命令发出的部件与直接发送相同；
  - `-v` 列出各部件，不打印内容。

## 兼容性变化

- **multipart 接口改为按 multipart 编码**：spec 里写着 `multipart/form-data` 的接口，以前被当成 urlencoded 表单发送，这本来就是错的。
  - 升级后已有缓存会在本地自动重建一次，不联网；
  - 在这类接口上用 `-f` 的命令仍可使用，值按文本部件发送。
- **multipart 接口上单独用 `-d`**：现在必须同时用 `-H 'Content-Type: ...'` 给出类型，否则退出 2，并提示改用 `-F`。
- **`-F` 的组合限制**：`-F` 不能与 `-d`、`-f` 或 `Content-Type` 头（`-H` 或 `-p header.Content-Type`）一起用，退出 2。
- **简单定义的 `body.type`**：现在只接受 json、form、multipart、xml、raw。
  - 写 `multipart` 的接口，以前按 JSON 发送且不带 Content-Type，现在真正按 multipart 发送；
  - 写了其他值的，该站点加载失败，所有命令退出 1，改正后恢复。
- **`config check`**：overlay 有结构错误时退出 1；没有 overlay 错误时行为不变。
- **保留名 `overlay`**：名为 `overlay` 的站点加载时会被跳过并警告，改名后才能使用。
- **配置文件**：只新增 `overlays/` 目录，v0.2.x 的配置不改也能继续使用。

## 安全提示

- `-F name=@path` 和 `-d @file` 会把本地文件发出去，只用于你明确给出的路径；`-f` 的值永远是文本。
- `-d @file` 仍沿用旧行为：在写保护检查之前读取，没有大小上限。
- Windows 上 UNC 路径（`\\host\share\...`）在打开时就会向该主机认证。

## 回滚到 v0.2.x

- 退回旧版后，对含 multipart 接口的站点，先删除 `<配置目录>/cache/specs/<site>.*`，再执行 `apic site refresh <site>`。否则旧版会继续使用新版写入的索引，这些接口无法正确发送。只执行 refresh 不够，服务端可能回 304。
- 回退前先撤掉以下配置：
  - overlay 文件：旧版会忽略它，改名后的命令名在旧版上不存在；
  - 简单定义中的 `body: {type: multipart}`：旧版会按 JSON 发送。
- 用了 `-F` 的命令在旧版上会报未知选项。
