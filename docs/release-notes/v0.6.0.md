# apic v0.6.0

## 新功能

- **`apic site export <站点> [--out 文件] [--allow-plaintext]`**：把一个站点连同它的简单定义、overlay 打成一个多文档 YAML 站点包（`---` 分隔，各文档以 `kind: site` / `definition` / `overlay` 标识）。
  - 站点文档保持 `${env:}` / `${exec:}` 引用不展开；简单定义和 overlay 按原文嵌入（注释保留，统一为 LF、去掉 BOM）。
  - 站点里有明文凭证时拒绝导出（退出 1，列出字段），`--allow-plaintext` 可强制。
  - OpenAPI 站点只导出站点文档：有 `source.url` 则保留；本地 `source.file` 不导出，并在 stderr 提示 spec 文件没有打进去。
  - 默认写 stdout；`--out` 指向已存在的文件时退出 1，不覆盖。
- **`apic site import <文件|URL|-> [--name 名称] [--force] [--yes]`**：安装站点包。
  - 来源可以是本地文件、`-`（stdin）或 http(s) URL（30 秒超时、正文最多 1 MiB）；下载失败的退出码与请求一致：网络 3、HTTP 4xx 为 4、5xx 为 5。
  - 站点包必须恰有一个 `kind: site`，至多各一个 `definition`、`overlay`；未知 kind 退出 1。简单站点必须带 definition。
  - 写入前先校验：站点结构、用简单加载器加载 definition、解析并套用 overlay。校验失败不写任何文件。写入失败会回滚本次已写的文件。
  - 写 `sites/<名称>.yaml`、`defs/<名称>.yaml`、`overlays/<名称>.yaml`；`source.file` 改写为 `defs/<名称>.yaml`。写完输出新站点的 `config check` 警告，stdout 一行摘要，如 `imported site mirror: sites/mirror.yaml defs/mirror.yaml`。
  - 站点名或目标文件已存在时退出 1；`--force` 覆盖 `sites/`、`defs/`、`overlays/` 下的文件。定义在 `config.yaml` 里的站点任何情况下都拒绝（apic 不改写 config.yaml）。
  - **会执行命令的站点包需要确认**：`auths` 里的 `${exec:...}` 和 `type: exec` 的 `command` 会让 apic 在使用凭证时运行命令。导入前先在 stderr 逐条列出（位置与命令文本）；有命令且没有 `--yes` 时退出 2，不写文件。
- **`apic site add <名称> --def <URL>`**：`--def` 支持 http(s) URL。下载（30 秒、1 MiB 上限）后用简单加载器校验，保存为 `defs/<名称>.yaml`（独占创建，已存在则退出 1），站点的 `source.file` 记为相对配置目录的 `defs/<名称>.yaml`。之后任何一步失败都会删除已下载的文件。本地路径的行为不变。

## 兼容性

- 纯新增：没有改动现有命令的行为；`--def` 以 `http://` 或 `https://` 开头时按 URL 处理（以前只能是本地路径）。
- `apic config check` 的输出不变，明文凭证检测与 `${exec:}` 扫描的代码抽成函数后与站点导出、导入共用。
- 回退到 v0.5.x：已导入的站点是普通的 `sites/`、`defs/`、`overlays/` 文件，继续可用。
